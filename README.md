# PERSONAL AI COMPANY

**「AIの力で、個人の可能性を最大化する。」**

あなた専属の「AI企業」をiPhoneで動かすためのアプリです。**この会社のいちばんの仕事は、あなたの生活を良くすること（QOL向上）**。事業づくりや収益化は、そのための手段の1つです。
7人のAI社員（社長・事業開発・調査・企画制作・秘書・財務監査・ライフインテリジェンス）がいて、あなたは「経営者」として仕事を頼んだり、提案を承認・却下したりします。

> いまは **Phase 4（お金をかせぐ準備）** までできています。業務を任せると、社長がチームを編成し、グループチャットで議論しながら、成果物の作成・監査・報告まで自動で進めます。**頼まなくても**事業開発担当が事業の候補を探し、調査担当が Web検索で調べ、社長が日報・週報・月報を書きます。有望な事業は、チームが**商品づくり・販売の準備**まで進めます。入ったお金・出たお金を記録すると、**もうけ**が分かります。大事なことは **iPhone に通知**が届きます。**SNSはSNS担当のAIが投稿案を作り**、承認したものを**あなたが投稿**します（「Xで開く」「Blueskyで開く」で文章入りの投稿画面が開きます）。記事などは**取材・外注なしで、AIだけで作り切ります**。**あなた（経営者）が行うのは、承認と、必要なときの指示だけです。**

## 1. いまできること・まだできないこと

| 画面 | いまできること（Phase 4 まで） | できないこと |
|---|---|---|
| ホーム | 会社の状況、**チームの進行状況**、承認待ちの数、今月・今日のAPI利用料、社長からの最新メッセージ、**最新の日報・週報・月報、新しい事業の候補、今月の収益**、最近の動き | — |
| 社員 | 7人のプロフィール、担当業務、実績、評価（★1〜5）、直接指示、**仕事から学んだことの記憶** | — |
| チャット | 社員と1対1で会話。社長に頼むと**業務を登録してチームで自動的に進める**。進行中のチームへの修正指示も社長が伝える | 1対1の会話の中での Web検索（調べものは業務として頼むと、チームの調査担当が調べます） |
| **グループチャット（チーム）** | 業務ごとのチームが、計画 → 議論 → 成果物の作成 → 監査（必要なら修正） → 社長の報告 まで**自動で進行**。**調査担当は Web検索で最新の情報を調べ、見たページのリンクを残す**。あなたはいつでも指示を書き込める | — |
| 業務管理 | 登録・一覧・絞り込み・状態の変更・履歴・API費用・重複防止。**チームの編成・進み具合・成果物（版ごと）** | — |
| 成果物 | 版ごとの保存、出力形式（レポート・メール文面・SNS投稿案・表・チェックリストなど）をチームが選ぶ、**コピー・ファイルで保存** | 外部への送信・投稿・公開は、アプリは行いません（あなたが行います。下の「大事なこと」参照） |
| 承認センター | 外部への操作の承認・却下・修正して再提出・保留。**成果物の最終確認**（承認で業務完了／差し戻しで修正指示）。承認後は「本文をコピー」「メールアプリで開く」「内容をコピー」で、あなたが実行 | アプリが外部で自動的に実行すること（あえて作っていません） |
| 報告書 | 社長の業務完了報告、**日報・週報・月報**（自動、またはボタン）。数字はシステムが集計した事実。記録したお金ともうけも入る | — |
| 財務管理 | **今月のもうけ**（収益 − 費用 − AI利用料 − 運用料金）、**月ごと・事業ごとのお金**、**入ったお金・出たお金の記録**（取り消しは理由つき）、API予算、使用額、社員別・業務別・日別の使用額、利用履歴 | 銀行やお店のサイトから自動で売上を取りこむこと（あなたが記録します） |
| 設定 | 会社名・理念・社内ルール、社員情報、API予算、AIモデル、緊急停止、全端末ログアウト、自動で動く頻度・Web検索のオン/オフ・見つけた候補を自動で調べるか、**iPhone のプッシュ通知** | — |
| **ホーム（今日のあなた）** | **毎日のQOLチェック**（気分・体調・睡眠・ストレスを1〜5でタップ・10秒）、**今日の習慣**（タップでチェック）、**もうすぐ起きること**、**目標の進み具合**、森野の週のふりかえり。その下に「あなたの会社の動き」 | — |
| **小さな習慣** | 毎日／週に何回かの習慣。続いた日数・今週の回数・4週間の達成率・この7日間。森野からのおすすめ（始めるかは自分で選ぶ）。改善提案から「習慣にする」 | — |
| **これから起きること** | 車検・契約の更新・税金・誕生日など（毎月・毎年のくり返しOK）。残り日数、30日・90日以内の出費の合計。近づいたら秘書の白石がお知らせ | カレンダーアプリとの連携 |
| **目標** | 数字の目標なら進み具合（%）と「遅れ気味」の表示、記録のグラフ。目標に届くと自動で「達成」。改善提案から「目標にする」 | — |
| **週のふりかえり** | 毎週月曜の朝、森野が先週（チェック・習慣・目標・予定）をふりかえり、よかったこと・気になること・来週の一歩と、おすすめの習慣を書く | — |
| **ライフ** | ライフ担当（森野 結）が**少しずつ質問**して生活情報を集める（1回1〜3問・理由つき・スキップOK）。生活情報はカテゴリごとに見られ、**履歴（変わる前の値）も残る**。修正・削除・「いまも同じ」の確認。**1・3・6・12か月の分析レポート**（グラフ＋数字＋森野のコメント）、**改善提案**（問題・根拠・メリット・費用・むずかしさ・優先度・おすすめの対応）。大事な提案は**チームで検討**。質問の頻度・カテゴリごとの「使う」「AIに渡す」を設定できる | 銀行やカードの明細の自動取りこみ（あなたが答える形） |
| **SNS運用** | SNS担当（春野 創太）が X・Bluesky 向けの投稿案を作る（自動、または「今すぐ投稿案を作る」）。1件ずつ承認に届き、承認後は「Xで開く」「Blueskyで開く」「文章をコピー」で**あなたが投稿** | アプリがSNSに投稿すること（あなたの方針で、あえて作っていません） |
| **事業開発** | 事業開発担当が**事業の候補を自分で探して保存**（自動、または「今すぐ仕事を探す」ボタン）。似た候補は保存しない。候補ごとに「チームで調べる」、状態（アイデア・調査中・有望・採用・保留・見送り）とメモ。**有望・採用の事業は「商品を作る」「販売の準備をする」をチームに任せられる**。事業ごとのお金 | 出品・投稿・登録（あなたが行います） |

**大事なこと：**
- **メール・メッセージは、あなたが自分で送ります。** AI社員は文面を作るところまでです。承認すると「本文をコピー」「メールアプリで開く」ボタンが出るので、それを使って送ってください。アプリが勝手に送ることは、これからもありません。
- **SNSへの投稿も、あなたが行います。** 承認すると「Xで開く」「Blueskyで開く」（文章が入った投稿画面が開く）と「文章をコピー」ボタンが出ます。
- そのほかの外部への操作（出品・登録など）は、**アプリは自動で実行しません。** 承認すると「内容をコピー」ボタンが出るので、必要ならあなたが行ってください。
- **note への記事の投稿**は、note に個人向けの自動投稿のしくみ（公式API）がないため、あなたが貼り付けて公開します。成果物の画面に「タイトルをコピー」「無料部分をコピー」「有料部分をコピー」「ハッシュタグをコピー」ボタンがあります。

## 2. かかるお金

| 項目 | 金額のめやす | 説明 |
|---|---|---|
| AI（OpenAI API）の利用料 | **月2,000円が上限**（初期設定） | 社員と1回会話すると、だいたい **0.2〜1円** です。**チームで1つの業務を仕上げると、だいたい 3〜15円**（6〜10回のAI呼び出し。Web検索を使うと +4〜6円）です（通常モデル GPT-5 mini の場合）。**仕事探し1回 約3〜10円、日報・週報1回 約1円**。毎日自動で動かすと（見つけた候補をチームが調べる分も含めて）、月に 300〜900円くらいが目安です。上限に近づくと自動で止まります。OpenAI には先払い（クレジット購入）で支払います。 |
| サーバー（Vercel） | 0円 | 無料プラン（Hobby）。個人で使う範囲なら無料です。※お金をかせぐ事業に本格的に使う場合は、Vercelの規約上、有料プラン（月20ドル程度）が必要になることがあります。 |
| データベース（Supabase） | 0円 | 無料プラン（保存容量 500MB）。※**1週間まったく使わないと一時停止**します（下の「こまったときは」参照）。 |

AIの料金は「使った量 × 料金表 × 為替レート」で計算して、アプリの中に毎回記録しています。為替レートは初期設定で 1ドル＝160円（少し高めにして安全側）です。

アプリに登録している料金表（100万トークンあたり・米ドル）：

| モデル | 入力 | 入力（キャッシュ） | 出力 | 使いどころ |
|---|---|---|---|---|
| `gpt-5-nano` | 0.05 | 0.005 | 0.40 | 最安。簡単な作業向け |
| `gpt-5-mini` | 0.25 | 0.025 | 2.00 | **通常業務（初期設定）** |
| `gpt-5` | 1.25 | 0.125 | 10.00 | 難しい業務（初期設定では使用不可） |

**Web検索の料金：** OpenAI の Web検索は「検索1回ごとの料金＋読んだページの量の料金」がかかります。正確な金額を確認できていないため、アプリでは**1回 0.025ドル（約4円）と多めに数えて**記録しています（実際より高めに表示されます）。

> ⚠️ 料金は変わることがあります。使い始める前に [OpenAI の料金ページ](https://openai.com/api/pricing/) で上の金額と同じか確認してください。違っていたら、プログラムの `src/lib/pricing.ts` を直す必要があります（開発者に依頼してください）。

## 3. セットアップ方法（最初に1回だけ）

パソコンで作業するのがおすすめです（スマホでもできますが、画面が小さいと大変です）。
全部で **30分〜1時間** くらいです。あわてなくて大丈夫です。

用意するもの：
- メールアドレス
- クレジットカード（OpenAI の利用料を払うため。サーバーとデータベースは無料）
- このプログラムが入っている GitHub のアカウント（すでにあります）

### 手順1：データベースを作る（Supabase）

データベースは「会社の記録を保存しておく金庫」のようなものです。

1. [https://supabase.com](https://supabase.com) を開いて「Start your project」を押し、GitHub アカウントでログインします。
2. 「New project」を押します。
3. 次のように入力します。
   - **Name（名前）**：`personal-ai-company`（なんでもOK）
   - **Database Password（パスワード）**：「Generate a password」を押して自動で作り、**メモ帳などに必ず保存**します。
   - **Region（場所）**：`Northeast Asia (Tokyo)` を選びます。
4. 「Create new project」を押して、2〜3分待ちます。
5. 画面の上のほうにある **「Connect」** ボタンを押します。
6. 「**Transaction pooler**」と書かれた欄の文字（`postgresql://` で始まる長い文字）をコピーします。
   - ※「Direct connection」ではなく、必ず **Transaction pooler** の方を使ってください（Vercelからつながるのはこちらです）。
7. コピーした文字の中の `[YOUR-PASSWORD]` の部分を、手順3で保存したパスワードに置き換えます。（`[` と `]` も消します）
8. できた文字を **「DATABASE_URL」** としてメモしておきます。

> 表（テーブル）を作る作業は不要です。アプリが最初に起動したときに、自動で作ります。

### 手順2：AI（OpenAI）のAPIキーを作る

APIキーは「AIを使うための合い言葉」です。**他の人に見せてはいけません。**
※ ChatGPT の月額プラン（ChatGPT Plus など）とは**別の契約**です。ChatGPT に課金していても、API の利用には別にクレジットの購入が必要です。

1. [https://platform.openai.com](https://platform.openai.com) を開いて「Sign up（登録）」または「Log in（ログイン）」します。（ChatGPT と同じアカウントで大丈夫です）
2. 右上の歯車マーク（Settings）→「**Billing（請求）**」を開きます。
3. 「Add payment details」でクレジットカードを登録し、「Add to credit balance」で少額（例：**5ドル**）のクレジットを購入します。
   - 「Auto recharge（自動チャージ）」は**オフ**のままにしておくと、使いすぎの心配がありません。
4. 念のため、Settings →「**Limits**」で、月の利用上限（Budget）を設定しておくと二重に安心です（例：10ドル）。
5. 左のメニュー（または Settings）から「**API keys**」を開き、「**Create new secret key**」を押します。
   - Name（名前）：`personal-ai-company`
   - Permissions（権限）：「All」のままで大丈夫です
6. 表示された `sk-` で始まる長い文字をコピーして、**「OPENAI_API_KEY」** としてメモします。
   - ※この文字は**一度しか表示されません**。なくしたら、作り直してください（古いキーは削除してOK）。

### 手順3：ログイン用のパスワードと暗号化キーを決める

1. **APP_PASSWORD**：アプリにログインするときのパスワードです。**12文字以上**で、他で使っていないものにしてください。（例：英字・数字・記号をまぜる）
2. **SESSION_SECRET**：ログイン状態を守るための「でたらめな文字」です。**32文字以上**の英数字を、キーボードで適当に打ってください。覚える必要はありません。
   - 例：`k3J9xQ2mVb7Lr8TzW1nYp5Hc6Df0GsAeUq4`（この例をそのまま使わないでください）

### 手順4：アプリを公開する（Vercel）

1. [https://vercel.com](https://vercel.com) を開いて「Sign Up」→「Continue with GitHub」でログインします。（プランは **Hobby** を選びます）
2. 「Add New…」→「Project」を押します。
3. このプログラムのリポジトリ（`PAC`）の横の「Import」を押します。
   - 一覧に出てこない場合は「Adjust GitHub App Permissions」から、このリポジトリへのアクセスを許可します。
4. 「Environment Variables（環境変数）」を開いて、次の4つを1つずつ追加します。（くわしくは下の「[必要な環境変数の一覧](#必要な環境変数の一覧)」）

   | Key（名前） | Value（値） |
   |---|---|
   | `DATABASE_URL` | 手順1でメモしたもの |
   | `OPENAI_API_KEY` | 手順2でメモしたもの |
   | `APP_PASSWORD` | 手順3で決めたパスワード |
   | `SESSION_SECRET` | 手順3で打ったでたらめな文字 |

   - Key は**大文字・小文字も含めて**この通りに入力します。
   - Value の前後に空白や改行が入らないよう注意してください。
   - 「Environments」は **Production・Preview・Development の全部** にチェックを入れたままにします。

5. 「Deploy」を押して、2〜3分待ちます。
6. 「Congratulations!」と出たら完成です。表示されたアドレス（`https://〜.vercel.app`）を開いてください。
7. ログイン画面が出たら、APP_PASSWORD を入力してログインします。

> 「初期設定が必要です」という画面が出たら、環境変数の入力にまちがいがあります。表示された名前の項目を確認し、Vercel の「Deployments」→ 一番上の「…」→「Redeploy」で作り直してください。

> **開発用ブランチについて：** このプログラムはいま `claude/personal-ai-company-app-0ztzzu` というブランチにあります。Vercel は普段 `main` ブランチを公開するので、GitHub で `main` に取り込んでから（プルリクエストをマージしてから）手順4を行うか、Vercel の「Settings → Git → Production Branch」でこのブランチ名を指定してください。

### 必要な環境変数の一覧

「環境変数」は、アプリに教える**秘密の設定メモ**です。プログラムには書かず、Vercel にだけ保存します。

| 名前 | 必須？ | 何に使う？ | どこで手に入れる？ | 形の例 |
|---|---|---|---|---|
| `DATABASE_URL` | **必須** | 会社の記録を保存するデータベースにつなぐ | Supabase →「Connect」→「Transaction pooler」（手順1） | `postgresql://postgres.abcd…:パスワード@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres` |
| `APP_PASSWORD` | **必須** | アプリにログインするパスワード | 自分で決める（12文字以上）（手順3） | `Sakura-2026-Kaisha!` のような文字 |
| `SESSION_SECRET` | **必須** | ログイン状態を守るための暗号化キー | 自分で適当に打つ（32文字以上）（手順3） | 英数字のでたらめな並び |
| `OPENAI_API_KEY` | **AIを使うなら必須** | 社員（AI）と会話する | OpenAI →「API keys」→「Create new secret key」（手順2） | `sk-proj-…`（とても長い） |
| `VAPID_PUBLIC_KEY`・`VAPID_PRIVATE_KEY` | 任意（通知を使うなら必須） | iPhone にプッシュ通知を送る | **アプリの「設定」→「通知」→「通知の鍵を作る」**で表示された値をコピー | 英数字の長い並び（2つ） |
| `CRON_SECRET` | 任意（おすすめ） | 毎朝（1日1回）に、**仕事探し・日報・週報を自動で行い**、止まっているチームの作業を続きから進める | 自分で適当に打つ（32文字以上の英数字） | 英数字のでたらめな並び |
| `AI_MOCK` | 入れない | 開発テスト用（本物のAIを呼ばずにテストの返事をする） | — | 本番では**設定しないでください** |

- `DATABASE_URL`・`APP_PASSWORD`・`SESSION_SECRET` のどれかが無いと、アプリを開いたときに「初期設定が必要です」という画面が出ます（足りない名前が表示されます）。
- `OPENAI_API_KEY` が無い場合、アプリは開けますが、社員との会話はできません（ホーム画面に赤いお知らせが出ます）。
- `VAPID_PUBLIC_KEY`・`VAPID_PRIVATE_KEY` が無くてもアプリは使えます（通知が届かないだけです）。`VAPID_PRIVATE_KEY` は秘密の値です。
- 通知の送り主として、Vercel が自動で用意するアプリのURL（`VERCEL_PROJECT_PRODUCTION_URL`）を使います。うまく届かないときだけ、`VAPID_SUBJECT` に `https://あなたのアプリのURL` を入れてください。
- `CRON_SECRET` が無くてもアプリは使えます。その場合、チームの作業は「業務を任せた直後」と「グループチャットを開いている間」に進みます。設定すると、それに加えて毎日1回（日本時間の朝7時半ごろ）続きを進めます。
- **自動の仕事探し・日報・週報**を使うには、`CRON_SECRET` を設定したうえで、アプリの「設定」→「自動で動く仕事」で頻度を「1日1回」か「週1回」にしてください（初期設定は「停止」）。設定画面に「設定済み／未設定」が表示されます。
- これらの値は**サーバー（Vercel）の中だけ**で使われ、iPhone の画面には送られません。OpenAI への呼び出しも、すべてサーバーから行います。
- 以前のバージョンで使っていた `ANTHROPIC_API_KEY` は**不要**になりました。Vercel に残っていたら削除してかまいません。
- Vercel では、公開用（Production）以外のアドレス（Preview）にも同じ値が必要です。環境変数の「Environments」は **Production・Preview・Development すべてにチェック**しておくと安心です。
- **環境変数を追加・変更したあとは、必ず「Redeploy（再デプロイ）」してください。** そうしないと新しい値が使われません。
  - やり方：Vercel のプロジェクト →「Deployments」→ 一番上の行の「…」→「Redeploy」→「Redeploy」
  - ⚠️ **「Redeploy」は、その行と同じ（古いかもしれない）コードで作り直すだけです。** GitHub の最新のコードを取り込むものではありません。

### 本番が最新のコードになっているか確かめる方法

1. Vercel のプロジェクト →「**Deployments**」を開きます。
2. 「**Production**」と書かれた一番新しい行を見ます。行の中に、もとになったコードの説明（コミットメッセージ）と7文字の番号（例：`e7679a6`）が表示されています。
3. GitHub のリポジトリのトップ画面に表示されている最新のコミットと、**番号が同じ**なら最新です。
4. 違う場合は、次のどちらかで最新のコードを公開します。
   - **自動で公開されるようにする（おすすめ）**：Vercel の「Settings → Git」で、Connected Git Repository が `yuuto543358-sketch/PAC` になっていること、「Production Branch」が GitHub のブランチ名（いまは `claude/personal-ai-company-app-0ztzzu`）と同じであることを確認します。こうしておくと、GitHub に新しいコードが保存されるたびに、自動で本番に公開されます。
   - **手動で公開する**：Deployments の一覧で、最新の番号の行（Preview と書かれていることもあります）の「…」→「**Promote to Production**」を押します。

### Vercel の設定のまとめ

ほとんどは自動で設定されます。次の表と同じになっているかだけ確認してください。

| 設定の場所 | 設定すること | 値 |
|---|---|---|
| プロジェクト作成時の「Framework Preset」 | 自動で選ばれます | `Next.js` |
| Build Command / Output Directory / Install Command | 変更しない（空欄のまま） | 自動 |
| Settings → Environment Variables | 上の4つを追加 | 「必要な環境変数の一覧」の通り |
| Settings → Git → Production Branch | 公開するブランチ | `main`（またはこのプログラムのブランチ名） |
| プラン | 無料でOK | Hobby |

プログラム側で次の設定をしてあるので、Vercel の画面で変更する必要はありません。
- **サーバーの場所を東京（hnd1）** にしています（`vercel.json`）。データベース（Supabase の東京）と近いので速くなります。
- **毎日1回の定期実行**（Vercel Cron）を設定しています（`vercel.json`）。無料プランでは1日1回までです。`CRON_SECRET` を設定したときだけ動きます。
- **Node.js のバージョンは 22** を使います（`package.json` の `engines`）。
- AI の返事を待つ時間を最大120秒にしています。
- データベースの表は、アプリが最初に起動したときに**自動で作成・更新**されます。

## 4. 使い方

### 社長に仕事を頼む（チームが自動で仕上げます）
1. 「ホーム」の「社長に相談」を押します。
2. 例：「低コストで始められる副業のアイデアを調べる業務をお願いします」と送ります。
3. 社長が業務を登録し、**チームを編成**します（リーダー・メンバー・監査役）。
4. チームが**グループチャット**で議論し、リーダーが成果物を作り、監査役（財務・監査担当）が確認します。問題があれば修正します（最大2回）。
5. 最後に社長が報告書を書き、**承認センターに「成果物の確認」**が届きます。
6. あなたは内容を見て、**承認する（業務完了）**か、**差し戻す（直してほしい点を書く）**だけです。

- 進み具合は「ホーム」の「チームの進行状況」や、業務の画面の「グループチャットを開く」で見られます。
- グループチャットの下の欄から、**いつでもチームに指示**を送れます（例：「対象を30代に絞って」）。
- チームから質問が来たら、グループチャットで答えると作業が再開します。
- 「業務を登録」画面から自分で登録するときも、「チームで自動的に進める」をオンにすると同じように進みます。
- 「一時停止」「再開」ボタンで、チームの作業を止めたり再開したりできます。

### AI社員に、自分で仕事を探してもらう（Phase 3）
1. 「メニュー」→「設定」→「**自動で動く仕事**」で、頻度を選んで保存します。
   - **1日1回**：毎晩、事業開発担当が事業の候補を探し、社長が日報を書きます（月曜は週報も）。
   - **週1回**：月曜の夜だけ、候補を探して週報を書きます。
   - **停止**（初期設定）：自動では何もしません。
2. 見つかった候補は「メニュー」→「**事業開発**」に並びます。ホームにも新しい候補が出ます。
3. 「見つけた候補を、チームに自動で調べさせる」がオンなら、チームが「本当にうまくいきそうか」を調べて報告書にします（同時に調べるのは2件まで）。
4. 候補を開いて、「有望」「採用」「保留」「見送り」などを選びます。メモも残せます。
5. 待てないときは、「事業開発」画面の「**今すぐ仕事を探す**」、「報告書」画面の「**日報を作る**」「**週報を作る**」を押すと、すぐに動きます。

- **「採用」にしても、勝手に何かが始まることはありません。** お金や外部への操作が必要なときは、必ず承認依頼が届きます。
- Web検索が心配なら、設定の「Web検索を使ってよい」をオフにしてください（AIの知識だけで考えます）。
- Web検索で見たページは、グループチャットや候補の画面に「Webで調べたページ」としてリンクが出ます。外部のサイトなので、内容が正しいとは限りません。

### 入ったお金・出たお金を記録する（Phase 4）
1. 「メニュー」→「財務管理」→「**入ったお金・出たお金を記録する**」を押します。
2. 「入ったお金（収益）」か「出たお金（費用）」を選び、金額・日付・種類を入れます。どの事業のお金かも選べます。
3. 「記録する」を押します。財務管理の「**今月のもうけ**」に反映されます。
- AIの利用料は自動で記録されるので、入れなくて大丈夫です。
- 記録は変更・削除できません。間違えたときは、その記録の「間違えたときは」→ 理由を書いて「取り消す」→ 正しく記録し直します。

### 商品づくり・販売の準備をチームに任せる（Phase 4）
1. 「事業開発」で候補を開き、「あなたの判断」で「**有望**」か「**採用**」にします。
2. 「次の一歩」の「**商品を作る**」または「**販売の準備をする**」を押します。
3. チームが、商品の中身や、販売ページの文章・値段・売る場所の候補・SNSの投稿文の案・あなたがやることのチェックリストを作り、成果物として届きます。
4. 出品・投稿・登録は、あなたが自分で行います。

**売る場所の選び方（あなたの方針）：** 「無料で始められる」「手続きができるだけ簡単」「手取りが多い（お客さんが集まっている場所も大事）」を総合的に判断して、商品ごとにいちばん良い場所を1つ選びます。
- チームは、候補を3つまで比べた表（手数料・1件あたりの手取り・手続きの簡単さ・お客さんの集まりやすさ）と、結論の1つを成果物に書きます。
- 参考にする主な候補：note（文章）／BOOTH（ダウンロードで渡すファイル）／ココナラ（人が作業するサービス）／メルカリShops（物）／BASE・Stripe（自分でお客さんを呼べるとき）。手数料は 2026年11月に調べた目安で、「事業開発」画面のいちばん下で見られます。
- 手数料は変わることがあるので、Web検索がオンのときは、チームが公式ページで確かめます。
- 方針を変えたいときは、「設定」→「社内ルール」に書くと、チームはそちらを優先します。

### 毎日の使い方（いちばん大事）
1. 朝、通知が届きます（「今日の習慣2つ・森野からの質問1問・『車検』まであと5日」のように、1日1回だけ）。
2. アプリを開くと、ホームのいちばん上が「**今日の調子は？**」です。気分・体調・睡眠・ストレスを1〜5でタップして「記録する」（10秒）。
3. 「**今日の習慣**」を、できたらタップしてチェックします。
4. 森野からの質問があれば答えます（スキップOK）。
5. 毎週月曜の朝に、森野から「**週のふりかえり**」が届きます。おすすめの習慣は「始める」を押したものだけが始まります。

**担当の社員**
- QOLチェック・習慣・目標・ふりかえり：ライフ担当 森野 結
- これから起きること：秘書 白石 結衣
- お金の目標：財務 堅田 守も確認
- 改善のための調査：調査・企画・財務のチーム
- AIを使うのは、ふりかえり（週1回・約1円）と月の分析（約1〜2円）だけです。チェック・習慣・予定・目標の記録は0円です。

### 暮らしのことを、AI社員に見てもらう（ライフ）
1. 「メニュー」→「**ライフ**」を開きます（質問が届くと、ホームにもお知らせが出ます）。
2. 森野からの質問に答えます。1回に1〜3問だけです。
   - 答えたくないときは「**スキップ**」、分からないときは「**分からない**」、あとで答えるときは「**後で答える**」（2日後にもう一度出ます）。
   - 質問の下に「質問の理由」が出ます。
3. 答えた内容は「**生活情報**」にたまります。
   - 料金が変わったときなどは、前の値も残ります（「変わりました：3,000円 → 4,000円」）。
   - 項目を開くと、グラフと履歴が見られます。直す・削除する・「いまも同じ」もここからです。
   - **削除すると、その記録と履歴は完全に消えます。**
4. 毎月1日に、森野が**分析レポート**と**改善提案**を作ります（3か月・6か月・年次は、区切りの月に）。「分析レポート」画面のボタンで、すぐ作ることもできます。
5. 改善提案を開くと、問題・根拠・メリット・費用・むずかしさ・優先度・おすすめの対応が見られます。
   - 「**チームで検討する**」を押すと、次の順で進んで報告書になります：社長がチームを作る → 調査担当が調べて比べる → 企画担当が具体案を作る → 財務・監査担当が費用とリスクを確認する → 社長が報告する。
   - 大事な提案は、自動でチームの検討になります（設定で止められます。同時に2件まで）。
6. 「ライフ」→「質問の頻度・カテゴリの設定」で、次のことを変えられます。
   - 質問の頻度（停止／少なめ／ふつう／多め）と、1回の質問数
   - カテゴリごとの「**使う**」（外すと質問しない）と「**AIに渡す**」（外すと分析のときOpenAIに送らない）

**守っていること**
- 分からない情報を、AIが勝手に数字で埋めることはしません。推測を使った提案には「推測を含む」と表示します。
- 数字（合計・平均・変化）は、プログラムが計算した事実です。AIは、それを読んでコメントを書くだけです。
- 契約変更・購入・申し込みは、提案するだけです。必要なときは承認依頼が届き、実行はあなたが行います。
- 質問づくりにAIは使いません（0円）。AIを使うのは分析のときだけで、記録がないときは呼びません。費用は月に30〜60円くらいの見込みです。今の予算の上限は変えていません。

### SNSの投稿案をAIに作ってもらう
1. 「メニュー」→「**SNS運用**」を開きます。
2. 「どのSNS向けに作る？」で X・Bluesky を選び、「投稿案を自動で作る頻度」を選んで保存します（ボタンで今すぐ作ることもできます）。
3. 投稿案が「承認」に届きます。内容を見て「承認する」を押します。直したいときは「内容を修正して再提出」→ 承認。
4. 「**Xで開く**」（または「Blueskyで開く」）を押すと、文章が入った投稿画面が開きます。内容を見て、**あなたが投稿ボタンを押します。**
- アプリがSNSに投稿することはありません。SNSの鍵の登録もいりません。

### iPhone に通知を届ける（Phase 4・最初に1回だけ）
1. Safari でアプリを開き、「共有」→「**ホーム画面に追加**」をします（iOS 16.4 以上が必要）。
2. アプリの「設定」→「通知」→「**通知の鍵を作る**」を押します。
3. 表示された2つの値（`VAPID_PUBLIC_KEY` と `VAPID_PRIVATE_KEY`）を、Vercel の環境変数に追加し、Redeploy します（手順4と同じやり方）。
4. **ホーム画面のアプリから**「設定」→「通知」を開き、「**この端末で通知を受け取る**」→「許可」を押します。
5. 「テスト通知」を押して、届くか確かめます。
- 届くお知らせ：承認のお願い・チームからの質問・自動の日報/週報/月報・新しい事業の候補・予算のお知らせ。どれを受け取るかは設定で選べます。

### 承認する
1. 社員が「メールを送りたい」などの外部への操作を提案すると、「承認」タブに数字が付きます。
2. 開いて、内容・実行先・費用・リスクを確認します。
3. 「承認する」「却下する」「保留する」のどれかを押します。内容を直したいときは「内容を修正して再提出」を使います（直した内容は、もう一度承認が必要です）。
4. **メール・メッセージの場合**は、承認すると文面のすぐ下に「本文をコピー」「メールアプリで開く」ボタンが出ます。
   - 「メールアプリで開く」を押すと、iPhone のメールアプリが宛先・件名・本文が入った状態で開きます。内容を見て、あなたが送信ボタンを押します。
   - LINE などで送るときは「本文をコピー」を押して、貼りつけてください。

### お金が心配になったら
- 「メニュー」→「設定」→「**緊急停止する**」を押すと、AIの呼び出しが全部止まります。
- 「メニュー」→「財務管理」で、今月いくら使ったかを確認できます。

## 5. 安全のしくみ

- **APIキーなどの秘密はサーバーだけに保存**しています。iPhone側（画面）には送られません。
- **承認していない操作は実行できない**仕組みです。承認するとき、内容から「指紋（ハッシュ）」を作って保存し、実行するときにもう一度計算して一致しないと実行しません。承認後に中身がすり替わった場合や、二重に実行しようとした場合も止まります。（いまは自動で実行する機能はありません。将来追加しても、この確認を必ず通ります）
- **AIを呼ぶ前に必ず予算を確認**します。費用は「最大でもこれくらい」という多めの見積もりで確認し、上限を超えそうなら呼びません。費用が分からないときも安全のため止めます。
- **AIの自動リトライはしません**（費用の二重計上を防ぐため）。チャットは1回の操作につきAIは1回だけ呼ばれます。
- **チームの自動進行にも上限があります**：1業務あたりの予算・AI呼び出し回数（20回）、作業回数（30回）、監査による修正（2回）。上限に達するとチームは止まり、あなたに知らせます。
- **失敗したとき**：同じ社員が2回続けて失敗すると、社長が担当を交代します。4回続けて失敗するとチームを止めて「失敗」にします（業務の画面の「再開」で続きから進められます）。
- **同じ業務を同時に2か所で進めない**仕組み（ロック）があり、二重に作業や費用が発生しません。
- グループチャットと成果物の本文も、**変更・削除できない記録**として保存されます（成果物は版ごとに保存）。
- OpenAI には会話の内容を**保存しない設定（store: false）**で送っています。
- **業務履歴・承認履歴・API利用記録・操作履歴は、データベースの仕組みで変更・削除できない**ようにしています。
- AI社員は、**会社のルール・自分の権限・予算・承認条件を変更できません**。変更できるのは設定画面からの経営者だけです。
- Webや外部の文書に書かれた「指示」は信頼できないデータとして扱うよう、AI社員に教えています。
- データベースは Supabase の公開API からは読み書きできないよう、すべての表に行レベルセキュリティ（RLS）をかけています。
- ログインに5回失敗すると、15分間ロックされます。
- **バックアップ：** Supabase の無料プランには自動バックアップがありません。大事なデータがたまってきたら、Supabase の「Database → Backups」から手動で書き出すか、有料プラン（自動バックアップ付き）を検討してください。

|---|---|
| 「初期設定が必要です」と出る | Vercel の環境変数を確認して、Redeploy してください（手順4）。 |
| `/api/health` を開くと、ログイン画面（アドレスが `/login` に変わる）が出る | 本番が**古いコードのまま**です（`/api/health` は新しいコードにしかありません）。上の「本番が最新のコードになっているか確かめる方法」で最新のコードを公開してください。 |
| ログインボタンを押すと「確認中」のまま動かない／エラーが出る | まず、ブラウザで **`https://（アプリのアドレス）/api/health`** を開きます。`"ok":true` なら、データベースへの接続は正常です。`"ok":false` のときは、`message` に原因と直し方が書いてあります。くわしく調べるときは、Vercel のプロジェクト →「Logs」で **`[pac]`** を検索すると、ログイン処理のどこで止まったかが分かります（下の「ログの見方」参照）。 |
| 「表示中にエラーが発生しました」と出る | データベースが一時停止している可能性があります。Supabase を開いて、プロジェクトの「Restore（再開）」を押してください。1〜2分で戻ります。 |
| 「OpenAI の APIキーが正しくありません」と出る | `OPENAI_API_KEY` が間違っているか、削除されています。OpenAI で作り直して Vercel に入れ直し、Redeploy してください。 |
| 「OpenAI の利用制限に達しました」と出る | OpenAI のクレジット残高が0になっている可能性があります。OpenAI の「Billing」で残高を確認し、必要ならクレジットを購入してください。 |
| 「モデル『…』を使う権限がないか…」と出る | 設定画面の「AIモデル」で別のモデル（例：GPT-5 nano）を選んでください。新しいアカウントでは使えるモデルが限られることがあります。 |
| 「今月のAPI利用額が上限に…」と出る | 予算を守るために止まっています。来月まで待つか、設定画面で上限を変えてください。 |
| 「緊急停止中」と出る | 設定画面で「緊急停止を解除する」を押してください。 |
| パスワードを忘れた | Vercel の環境変数 `APP_PASSWORD` を新しいものに変えて、Redeploy してください。 |
| 誰かにパスワードを知られたかも | 上と同じ方法でパスワードを変え、設定画面の「すべての端末からログアウト」を押してください。 |

### ログの見方（Vercel の Logs）

ログイン時には、次のような行が順番に出ます。最後に出ている行の「次の処理」で止まっています。

| ログに出る文字 | 意味 |
|---|---|
| `[pac][login] start` | ログイン処理が始まった |
| `[pac][login] env ok` | 環境変数はそろっている |
| `[pac][db] create client {"host":…,"kind":…}` | データベースへの接続を準備した（`kind` が `supabase-transaction-pooler` なら正しい接続方式） |
| `[pac][login] db ping ok` | データベースにつながった |
| `[pac][login] schema up to date` | 表はすでにできている |
| `[pac][login] db ready` | データベースの準備完了 |
| `[pac][login] attempt recorded {"ok":true}` | パスワードが正しかった |
| `[pac][login] cookie set` → `redirect to home` | ログイン完了 |
| `FAILED …` | ここでエラーになった（`code` と `message` に理由） |

パスワードや接続文字列などの秘密情報は、ログには出しません。

### データベースに「固まった処理」が残っている場合（めったにありません）

アプリは、30秒以上放置された処理を自動で片付けるようになっています。それでも直らないときは、Supabase の「SQL Editor」で次の文を実行すると、放置された処理を終了できます。

```sql
select pg_terminate_backend(pid)
from pg_stat_activity
where datname = current_database()
  and state like 'idle in transaction%'
  and pid <> pg_backend_pid();
```

### 決めたこと（技術的な判断）
- **ログイン方式**：最初の候補は Supabase Auth でしたが、使う人が1人だけなので「パスワード＋暗号化クッキー」方式にしました。設定項目が少なく、Supabase 側の追加設定も不要です。
- **データベースへの接続**：サーバーから直接つなぎ、画面（iPhone側）からは一切つながない方式にしました。そのため Supabase の公開キーは使いません。
- **AIの提供元**：OpenAI API のみを使います（Anthropic / Claude は使いません）。
- **AIモデル**：通常は低価格な **GPT-5 mini**、難しい業務だけ **GPT-5**（初期設定では高性能モデルは無効）。いちばん安い **GPT-5 nano** も選べます。
- **定期実行**：Vercel 無料プランでは1日1回までなので、1日1回（日本時間の朝7時半ごろ）の実行にしています（通知が夜中に鳴らないよう、朝にしています）。同じ日に2回呼ばれても、仕事探し・日報・週報は1回しか行いません。
- **取材・外注・広告はしない**：記事や商品は、AIの知識とWeb調査だけで作る（経営者の方針）。架空の取材・架空の人の声・根拠のない数字は書かない（監査役も確認）。
- **SNS運用**：SNS担当のAIが投稿案を作り、経営者が承認して、経営者自身が投稿する（経営者の方針）。アプリは投稿しない（投稿画面を文章入りで開くリンクとコピーだけ）。note も個人向けの自動投稿のしくみがないため貼り付け。
- **売る場所**：経営者の方針（無料・手続きが簡単・手取りが多い、を総合判断）で、チームが商品ごとに1つ選ぶ（`src/lib/sales-channels.ts` に方針と手数料の目安）。
- **メール**：外部とのメールのやり取りは、必要なら経営者が自分で行う（経営者の方針）。アプリは文面を作り、送るための「コピー」「メールアプリで開く」を出すだけです。サーバー側でも、メールの自動送信は拒否するようにしてあります。
- **Web調査**：OpenAI の Web検索機能を使います（初期設定でオン。設定でオフにできます）。費用を抑えるため、使うのは「調査担当の議論での発言（1回まで）」と「事業開発担当の仕事探し（2回まで）」だけです。

### 新しい社員・部署を追加するには
`src/lib/db/seed.ts` の `SEED_DEPARTMENTS` / `SEED_EMPLOYEES` に追加すると、次の起動時に自動で登録されます（すでにある社員は上書きされません）。社員の役割 `role_key` で権限が決まり、社長（`president`）だけが他の社員に業務を割り当てられます。表の構造を変えるときは、`src/lib/db/schema.ts` の `MIGRATIONS` の末尾に新しいバージョンを追加してください（既存のものは書き換えない）。
