# PERSONAL AI COMPANY

**「AIの力で、個人の可能性を最大化する。」**

あなた専属の「AI企業」をiPhoneで動かすためのアプリです。
6人のAI社員（社長・事業開発・調査・企画制作・秘書・財務監査）がいて、あなたは「経営者」として仕事を頼んだり、提案を承認・却下したりします。

> いまは **Phase 1（会社の基盤）** までできています。できること・まだできないことは下の表を見てください。

## 1. いまできること・まだできないこと

| 画面 | いまできること（Phase 1） | まだできないこと |
|---|---|---|
| ホーム | 会社の状況、業務の数、承認待ちの数、今月・今日のAPI利用料、社長からの最新メッセージ、重要なお知らせ | 収益の記録（Phase 4）、自動の日次報告（Phase 2〜3） |
| 社員一覧・社員詳細 | 6人のプロフィール、担当業務、実績、評価（★1〜5）、直接指示 | 経験を記憶して成長する機能（Phase 2） |
| チャット | 社員と会話。社長に頼むと、社長が担当者を選んで**業務を登録**。メール送信などを頼むと**承認依頼を提出** | Web検索・資料の自動作成（Phase 3） |
| 業務管理 | 登録・一覧・絞り込み（担当・部署・状態・優先度・発生日・完了日）・状態の変更・成果物の記録・履歴・API費用。似た業務の**重複登録を防止** | 社員がAIで自動的に業務を進める機能（Phase 2〜3） |
| 承認センター | 承認する・却下する・内容を修正して再提出・保留。履歴は消せません | 承認後に**実際に外部へ実行する機能**（Phase 4） |
| 財務管理 | API予算、使用額、社員別・業務別・日別の使用額、利用履歴、運用料金（手入力） | 事業別の収益・費用（Phase 4） |
| 設定 | 会社名・理念・社内ルール、社員情報（名前・アバターなど）、API予算、AIモデル、緊急停止、全端末ログアウト | 自動実行（頻度の保存のみ可。実行はPhase 3）、プッシュ通知（Phase 3） |
| 事業開発・報告書 | 「準備中」と表示されます | Phase 2〜4で実装 |

**大事なこと：** 承認ボタンを押しても、今はまだメール送信などの「外部への実行」は行われません（その機能がまだ無いため）。承認したという記録だけが残ります。

## 2. かかるお金

| 項目 | 金額のめやす | 説明 |
|---|---|---|
| AI（Claude API）の利用料 | **月2,000円が上限**（初期設定） | 社員と1回会話すると、だいたい **0.1〜0.5円** です（軽量モデル Claude Haiku 5.5 の場合）。上限に近づくと自動で止まります。 |
| サーバー（Vercel） | 0円 | 無料プラン（Hobby）。個人で使う範囲なら無料です。※お金をかせぐ事業に本格的に使う場合は、Vercelの規約上、有料プラン（月20ドル程度）が必要になることがあります。 |
| データベース（Supabase） | 0円 | 無料プラン（保存容量 500MB）。※**1週間まったく使わないと一時停止**します（下の「こまったときは」参照）。 |

AIの料金は「使った量 × 公式料金 × 為替レート」で計算して、アプリの中に毎回記録しています。為替レートは初期設定で 1ドル＝160円（少し高めにして安全側）です。

## 3. セットアップ方法（最初に1回だけ）

パソコンで作業するのがおすすめです（スマホでもできますが、画面が小さいと大変です）。
全部で **30分〜1時間** くらいです。あわてなくて大丈夫です。

用意するもの：
- メールアドレス
- クレジットカード（AIの利用料を払うため。サーバーとデータベースは無料）
- このプログラムが入っている GitHub のアカウント（すでにあります）

### 手順1：データベースを作る（Supabase）

データベースは「会社の記録を保存しておく金庫」のようなものです。

1. [https://supabase.com](https://supabase.com) を開いて「Start your project」を押し、GitHub アカウントでログインします。
2. 「New project」を押します。
3. 次のように入力します。
   - **Name（名前）**：`personal-ai-company`（なんでもOK）
   - **Database Password（パスワード）**：「Generate a password」を押して自動で作り、**メモ帳などに必ず保存**します。
   - **Region（場所）**：`Northeast Asia (Tokyo)` を選びます。
4. 「Create new project」を押して、2〜3分待ちます。
5. 画面の上のほうにある **「Connect」** ボタンを押します。
6. 「**Transaction pooler**」と書かれた欄の文字（`postgresql://` で始まる長い文字）をコピーします。
   - ※「Direct connection」ではなく、必ず **Transaction pooler** の方を使ってください（Vercelからつながるのはこちらです）。
7. コピーした文字の中の `[YOUR-PASSWORD]` の部分を、手順3で保存したパスワードに置き換えます。（`[` と `]` も消します）
8. できた文字を **「DATABASE_URL」** としてメモしておきます。

> 表（テーブル）を作る作業は不要です。アプリが最初に起動したときに、自動で作ります。

### 手順2：AI（Claude）のAPIキーを作る

APIキーは「AIを使うための合い言葉」です。**他の人に見せてはいけません。**

1. [https://platform.claude.com](https://platform.claude.com) を開いて、アカウントを作ります。
2. 「Billing（請求）」の画面で、クレジットカードを登録し、少額（例：5ドル）のクレジットを購入します。
3. 念のため、「Limits（上限）」の画面で **月の利用上限** を設定しておくと二重に安心です（例：15ドル）。
4. 「API Keys」の画面で「Create Key」を押し、名前（例：`personal-ai-company`）を付けて作ります。
5. 表示された `sk-ant-` で始まる文字をコピーして、**「ANTHROPIC_API_KEY」** としてメモします。
   - ※この文字は一度しか表示されません。なくしたら作り直してください。

### 手順3：ログイン用のパスワードと暗号化キーを決める

1. **APP_PASSWORD**：アプリにログインするときのパスワードです。**12文字以上**で、他で使っていないものにしてください。（例：英字・数字・記号をまぜる）
2. **SESSION_SECRET**：ログイン状態を守るための「でたらめな文字」です。**32文字以上**の英数字を、キーボードで適当に打ってください。覚える必要はありません。
   - 例：`k3J9xQ2mVb7Lr8TzW1nYp5Hc6Df0GsAeUq4`（この例をそのまま使わないでください）

### 手順4：アプリを公開する（Vercel）

1. [https://vercel.com](https://vercel.com) を開いて「Sign Up」→「Continue with GitHub」でログインします。（プランは **Hobby** を選びます）
2. 「Add New…」→「Project」を押します。
3. このプログラムのリポジトリ（`PAC`）の横の「Import」を押します。
   - 一覧に出てこない場合は「Adjust GitHub App Permissions」から、このリポジトリへのアクセスを許可します。
4. 「Environment Variables（環境変数）」を開いて、次の4つを1つずつ追加します。

   | Key（名前） | Value（値） |
   |---|---|
   | `DATABASE_URL` | 手順1でメモしたもの |
   | `ANTHROPIC_API_KEY` | 手順2でメモしたもの |
   | `APP_PASSWORD` | 手順3で決めたパスワード |
   | `SESSION_SECRET` | 手順3で打ったでたらめな文字 |

5. 「Deploy」を押して、2〜3分待ちます。
6. 「Congratulations!」と出たら完成です。表示されたアドレス（`https://〜.vercel.app`）を開いてください。
7. ログイン画面が出たら、APP_PASSWORD を入力してログインします。

> 「初期設定が必要です」という画面が出たら、環境変数の入力にまちがいがあります。表示された名前の項目を確認し、Vercel の「Deployments」→ 一番上の「…」→「Redeploy」で作り直してください。

> **開発用ブランチについて：** このプログラムはいま `claude/personal-ai-company-app-0ztzzu` というブランチにあります。Vercel は普段 `main` ブランチを公開するので、GitHub で `main` に取り込んでから（プルリクエストをマージしてから）手順4を行うか、Vercel の「Settings → Git → Production Branch」でこのブランチ名を指定してください。

### 手順5：iPhone のホーム画面に追加する

1. iPhone の **Safari** で、手順4のアドレスを開きます。（Chrome ではなく Safari を使ってください）
2. 画面下の **共有ボタン**（四角から矢印が出ているマーク）を押します。
3. 「**ホーム画面に追加**」を押します。
4. 名前を確認して「追加」を押します。
5. ホーム画面に青いアイコン（ビルと星のマーク）ができます。タップすると、アプリのように全画面で開きます。

## 4. 使い方

### 社長に仕事を頼む
1. 「ホーム」の「社長と話す」、または「社員」→「天城 翔」→「チャットする」を押します。
2. 例：「低コストで始められる副業のアイデアを調べる業務をお願いします」と送ります。
3. 社長が担当者を選んで、業務を登録します。登録された業務は「業務」タブで見られます。

### 承認する
1. 社員が「メールを送りたい」などの外部への操作を提案すると、「承認」タブに数字が付きます。
2. 開いて、内容・実行先・費用・リスクを確認します。
3. 「承認する」「却下する」「保留する」のどれかを押します。内容を直したいときは「内容を修正して再提出」を使います（直した内容は、もう一度承認が必要です）。

### お金が心配になったら
- 「メニュー」→「設定」→「**緊急停止する**」を押すと、AIの呼び出しが全部止まります。
- 「メニュー」→「財務管理」で、今月いくら使ったかを確認できます。

### 初期の予算設定（設定画面で変更できます）

| 項目 | 初期値 | 意味 |
|---|---|---|
| 月間上限 | 2,000円 | これ以上は絶対に使わない金額 |
| 通常利用目標 | 1,500円 | これを超えるとホーム画面で注意が出ます |
| 緊急停止ライン | 1,800円 | ここに達すると、その月は新しいAI処理が止まります |
| 1業務あたりの上限 | 30円 | 1つの業務で使えるAI費用 |
| 1日あたりの上限 | 50円 | 1日で使えるAI費用 |
| 1業務の呼び出し回数 | 8回 | 1つの業務でAIを呼べる回数 |
| 1日の呼び出し回数 | 100回 | 1日にAIを呼べる回数 |
| 1分の呼び出し回数 | 6回 | 無限ループ防止のための上限 |

## 5. 安全のしくみ

- **APIキーなどの秘密はサーバーだけに保存**しています。iPhone側（画面）には送られません。
- **承認していない操作は実行できない**仕組みです。承認するとき、内容から「指紋（ハッシュ）」を作って保存し、実行するときにもう一度計算して一致しないと実行しません。承認後に中身がすり替わった場合や、二重に実行しようとした場合も止まります。（実行機能そのものは Phase 4 で追加）
- **AIを呼ぶ前に必ず予算を確認**します。費用は「最大でもこれくらい」という多めの見積もりで確認し、上限を超えそうなら呼びません。費用が分からないときも安全のため止めます。
- **AIの自動リトライはしません**（費用の二重計上を防ぐため）。1回の操作につきAIは1回だけ呼ばれます。
- **業務履歴・承認履歴・API利用記録・操作履歴は、データベースの仕組みで変更・削除できない**ようにしています。
- AI社員は、**会社のルール・自分の権限・予算・承認条件を変更できません**。変更できるのは設定画面からの経営者だけです。
- Webや外部の文書に書かれた「指示」は信頼できないデータとして扱うよう、AI社員に教えています。
- データベースは Supabase の公開API からは読み書きできないよう、すべての表に行レベルセキュリティ（RLS）をかけています。
- ログインに5回失敗すると、15分間ロックされます。
- **バックアップ：** Supabase の無料プランには自動バックアップがありません。大事なデータがたまってきたら、Supabase の「Database → Backups」から手動で書き出すか、有料プラン（自動バックアップ付き）を検討してください。

## 6. こまったときは

| こまったこと | どうすればいいか |
|---|---|
| 「初期設定が必要です」と出る | Vercel の環境変数を確認して、Redeploy してください（手順4）。 |
| 「表示中にエラーが発生しました」と出る | データベースが一時停止している可能性があります。Supabase を開いて、プロジェクトの「Restore（再開）」を押してください。1〜2分で戻ります。 |
| 「APIキーが正しくありません」と出る | ANTHROPIC_API_KEY が間違っているか、削除されています。作り直して Vercel に入れ直し、Redeploy してください。 |
| 「今月のAPI利用額が上限に…」と出る | 予算を守るために止まっています。来月まで待つか、設定画面で上限を変えてください。 |
| 「緊急停止中」と出る | 設定画面で「緊急停止を解除する」を押してください。 |
| パスワードを忘れた | Vercel の環境変数 `APP_PASSWORD` を新しいものに変えて、Redeploy してください。 |
| 誰かにパスワードを知られたかも | 上と同じ方法でパスワードを変え、設定画面の「すべての端末からログアウト」を押してください。 |

## 7. 今後の予定（Phase 2〜4）

| Phase | 内容 |
|---|---|
| Phase 2：AI社員の連携 | 社長が社員に業務を割り当てて、担当社員がAIで業務を進める／社員同士の連携／報告書／社内知識・記憶の蓄積 |
| Phase 3：自律的な業務 | 自主的な仕事の発見／定期実行（1日1回まで、実行前に予算確認）／Web調査／事業候補の発掘／企画・制作／自動報告／通知 |
| Phase 4：収益化 | 事業案件管理／収益・費用管理／商品制作／販売準備／**承認後の実行機能**（メール送信など） |

### 決めたこと（技術的な判断）
- **ログイン方式**：最初の候補は Supabase Auth でしたが、使う人が1人だけなので「パスワード＋暗号化クッキー」方式にしました。設定項目が少なく、Supabase 側の追加設定も不要です。
- **データベースへの接続**：サーバーから直接つなぎ、画面（iPhone側）からは一切つながない方式にしました。そのため Supabase の公開キーは使いません。
- **AIモデル**：通常は低価格な **Claude Haiku 5.5**、難しい業務だけ **Claude Opus 5.5**（初期設定では高性能モデルは無効）。
- **定期実行**：Vercel 無料プランでは1日1回までなので、Phase 3 では1日1回の実行を前提に設計します。

### これから決めたいこと（経営者に確認したい点）
1. メール送信（Phase 4）にどのサービスを使うか（例：Gmail、Resend など）。
2. 収益化の検証で使う販売サービス（例：note、BOOTH、Stripe など）。
3. Web調査（Phase 3）で、AIの検索機能を使うか（1回あたり数円の追加費用がかかります）。
4. 通知の方法（iPhoneのプッシュ通知、メールなど）。

## 8. 開発者向けの情報

### 構成
- Next.js 16（App Router・Server Actions）/ TypeScript / Tailwind CSS 4
- PostgreSQL（Supabase）に `postgres`（postgres.js v4）で接続。表の作成は `src/lib/db/schema.ts` を起動時に自動適用
- AI：`@anthropic-ai/sdk`（構造化出力 `messages.parse` + Zod）
- PWA：`public/manifest.webmanifest`、`public/sw.js`（オフライン画面のみ。会社データはキャッシュしない）

### 主なファイル
| 場所 | 役割 |
|---|---|
| `src/lib/budget.ts` | AI呼び出し前の予算チェック（ロック付き予約 → 確定） |
| `src/lib/ai/client.ts` | AI呼び出しの唯一の入口（必ず予算チェックを通る） |
| `src/lib/ai/chat.ts`・`prompts.ts` | 社員チャット（業務登録・承認依頼の抽出） |
| `src/lib/repo/approvals.ts` | 承認（指紋・状態遷移・実行ガード `executeApprovedAction`） |
| `src/lib/repo/tasks.ts` | 業務（重複検出・状態遷移・履歴） |
| `src/lib/db/schema.ts` | テーブル定義・変更禁止トリガー・RLS |
| `src/lib/auth/*`・`src/proxy.ts` | ログイン（HMAC署名クッキー） |

### ローカルで動かす
```bash
npm install
cp .env.example .env.local   # 値を入れる（AI_MOCK=1 にすると本物のAIを呼ばない）
npm run dev
```

### テスト
```bash
# 単体・結合テスト（PostgreSQL が必要。テスト用DBは毎回作り直されます）
TEST_DATABASE_URL=postgres://postgres@127.0.0.1:5432/pac_test npm test

# iPhone画面での操作テスト（サーバーを AI_MOCK=1 で起動してから。Playwright が必要）
BASE_URL=http://localhost:3000 APP_PASSWORD=... npm run e2e
```

テスト内容：予算上限（月・日・業務・回数・1分あたり）、同時アクセスでも上限を超えないこと、費用不明時の安全側記録、承認なしでは実行できないこと、二重実行防止、承認内容の改ざん検出、記録の削除・変更禁止、重複業務の検出、チャットからの業務登録と承認依頼、ログイン、緊急停止など。

### 新しい社員・部署を追加するには
`src/lib/db/seed.ts` の `SEED_DEPARTMENTS` / `SEED_EMPLOYEES` に追加すると、次の起動時に自動で登録されます（すでにある社員は上書きされません）。社員の役割 `role_key` で権限が決まり、社長（`president`）だけが他の社員に業務を割り当てられます。表の構造を変えるときは、`src/lib/db/schema.ts` の `MIGRATIONS` の末尾に新しいバージョンを追加してください（既存のものは書き換えない）。
